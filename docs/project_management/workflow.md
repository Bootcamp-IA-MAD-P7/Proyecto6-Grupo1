# Flujo de proyecto

## Descubrimiento

1. Proponer varias ideas de negocio.
2. Compararlas por valor, datos, viabilidad multiclase, ética y capacidad de demo.
3. Seleccionar una idea de forma explícita.
4. Crear la primera spec de producto.

## Desarrollo

1. Descomponer el trabajo por specs y tareas verificables.
2. Trabajar en ramas pequeñas desde `dev`.
3. Integrar mediante Pull Requests.
4. Mantener el nivel esencial ejecutable.
5. Añadir niveles posteriores solo sobre evidencia estable.

## Cierre

1. Congelar código y modelo.
2. Ejecutar validación automática y manual.
3. Sincronizar métricas, informes, README y presentaciones.
4. Crear release hacia `main`.
5. Etiquetar una versión únicamente después de validar el despliegue.
