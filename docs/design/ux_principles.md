# Principios UX

## Orientación a tareas

La aplicación debe ayudar a completar una decisión real, no limitarse a exponer un formulario del modelo.

## Explicación multiclase

La interfaz deberá comunicar clase predicha, confianza, alternativas relevantes y significado operativo sin abrumar al usuario.

## Estados completos

Cada flujo contemplará carga, vacío, éxito, error, datos inválidos, servicio no disponible y falta de confianza suficiente.

## Accesibilidad

- Navegación mediante teclado.
- Contraste verificable.
- Etiquetas comprensibles.
- No depender únicamente del color.
- Gráficos con texto alternativo o explicación equivalente.

## Confianza

- Mostrar versión o fecha del modelo cuando aporte valor.
- Explicar limitaciones y alcance de la predicción.
- No utilizar lenguaje que sugiera certeza absoluta.

## Evidencia

Los cambios relevantes de interfaz deberán incluir capturas, comprobación responsive y revisión de los flujos afectados.
